## B1. Clicking a case shows only a "Read from the start" button

**Steps.** Open the demo, pick Case law in the drawer, click *Commissioner of Taxation v Bendel*
(or open `/#/corpus/2026-hca-18`).

**Expected.** The judgment itself, readable and scrollable.

**Actual.** A landing page with the heading, an empty **Contents** block and one
**Read from the start** button. Following the button opens `#/node/2026-hca-18`,
which renders empty: the root node carries no text. The only readable content in
the corpus is `2026-hca-18:summary`, a 2,771-character machine-generated summary.

**Cause.** Two separate things:

1. `ui/app.js` `showCorpus()` (line ~846) renders an outline plus a "read from the
   start" call to action for every corpus. A case is a single-document corpus, so
   there is no outline to show and the call to action is the whole page.
2. The corpus actually holds no judgment text. `examples/au-tax/sources.toml`
   ingested the HCA case as a summary only (2 nodes: root + summary), so even the
   node route has nothing to display.

**Proposed fix.**
- Treat single-document corpora (kind `case`, and any corpus whose root has no
  children) as a document: the drawer links straight to `#/node/<root-id>`, and
  `#/corpus/<id>` redirects there instead of rendering a landing page.
- Never render the "Read from the start" call to action when the outline is empty.
- Data side, separate change: ingest the judgment body and its paragraphs rather
  than a summary, so a case reads like a case.

## B2. Remove the footer disclaimer

**Where it comes from.**
- `crates/meowlaw-server/src/config.rs` line ~157: default `footer` string
  "Not legal advice. Check every source against the official version."
- `ui/app.js` `disclaimer()` (line ~449) renders `BRAND.footer` on the reader,
  search results, corpus page and home page.
- The deployed demo config also sets `branding.footer`.

**Proposed fix.** Delete the built-in default (empty footer renders nothing), drop
the string from the example and demo configs. Keep the `footer` option so an
operator can still set their own.

## B3. Container pages should not exist

**Steps.** Open `https://meowlaw.blaqsheep.xyz/#/node/itaa-1997%3Apt1-3`.

**Expected.** Only content nodes have pages; containers (Part, Division,
Subdivision, Chapter) live in the API tree and in the drawer.

**Actual.** A full reader page for Part 1-3, including a "Contents" list of its
children.

**Cause.** `showNode()` renders any id it is given, containers included.
Breadcrumbs (`ui/app.js` ~line 571) and the reader's "Contents" list
(`renderChildren`) also link to container ids, so the pages are reachable from
normal navigation, not just typed URLs.

**Proposed fix.**
- On a container id, expand the tree to that node and replace the hash with its
  first leaf, so the reader always lands on content.
- Render container crumbs as plain text rather than links.
- Point the reader's "Contents" list at leaves only (or drop it, since the drawer
  already shows the hierarchy).

## B4. Remove the reader meta line "AU-CTH · as at 2026-07-01 · Compilation 266"

**Where.** `ui/app.js` line ~576 builds `meta` from jurisdiction, "as at" date and
compilation number; line ~582 renders it under the title on every node page.

**Proposed fix.** Remove the line from the reader. Jurisdiction, currency and
compilation stay available through the API and the source list, so nothing is lost.
